# CertFlow — 新人資格取得・費用申請管理ツール

資格ごとの「会社負担・上限回数・報奨金・目標点数」を分かりやすくし、
**申請 → 承認 → 結果報告 → 費用申請 → 実績** までの流れを1つの画面群で管理する
学習用デモです。

> **架空の条件**
> 実在の資格名（日商簿記3級・ITパスポート・基本情報技術者試験・TOEIC・
> SAP関連資格・応用情報技術者試験など）を**例として**使用しています。
> 会社名・社員名・費用負担制度・報奨金額・TOEICの目標点数・サンプル申請データは
> **すべて架空**です。

---

## どう起動するか（サーバー不要）

1. このフォルダの `index.html` をブラウザ（Chrome / Edge 推奨）で開くだけです。
   - サーバーやインターネットは不要です。
   - ダブルクリックで開くだけで動作します。
2. データはブラウザ内部の **localStorage**（ブラウザ内の簡易データ保存領域）に保存されます。
   - ブラウザを閉じてもデータは残ります。
   - 確認方法：ブラウザの開発者ツール（F12）→「アプリケーション」タブ →
     「ローカルストレージ」で `certflow_data` というキーを確認できます。
3. 動作を最初からやり直したいときは、ヘッダーの **「サンプルデータを初期化」** ボタンを押します。

## 技術構成

- HTML / CSS / JavaScript のみ（フレームワーク・外部API・サーバーなし）
- 画面は1つの HTML + JavaScript で切り替える方式（いわゆる SPA 構造）
- データは localStorage に JSON 形式で保存

## 保存するデータ（localStorage の中身）

1つのキー `certflow_data` に、次の7つの配列をまとめて保存します。

| 配列 | 内容 |
|---|---|
| employees | 利用者（新入社員／上司）。`joinedDate`（入社日）を持つ |
| qualifications | 資格制度マスタ（正式に登録された資格の台帳） |
| qualificationCheckRequests | 未登録資格の制度確認申請 |
| examApplications | 受験申請 |
| examReports | 試験結果報告・受験履歴 |
| reimbursementRequests | 費用申請 |
| achievementRecords | 資格取得実績（報奨金予定額を含む） |

詳しい項目の意味は `CLAUDE.md` を参照してください。

## できること（全体）

**新入社員（役割切替で「新入社員」）**
- ダッシュボードで自分の状態（申請中・承認済み・結果未報告・取得資格・費用申請中・報奨金予定額）を一覧確認
- 資格制度一覧の確認（会社負担可否・上限回数・合否条件・報奨金）と、資格名／カテゴリ／負担可否での検索
- 検索結果が0件の場合は「制度確認を申請する」ボタンから申請画面へ移動
- 未登録資格の制度確認申請（資格名・カテゴリ・概要・申請理由）と、自分の申請一覧（ステータス確認）
- 受験申請（資格・受験日は今日以降・予定費用・受験目的を入力）。**会社負担対象外**の資格では「自己負担」と明示
- 試験結果報告（承認済みの申請のみ）。合否／点数・実際費用・領収書提出有無・取得日を入力
- 報告後は**受験履歴**に保存され、合否・負担条件に応じて**費用申請の自動生成・取得実績・報奨金**が処理される
- 自分の申請履歴（制度確認／受験／費用申請のタブ、検索・ステータス絞り込み）と資格取得実績（報奨金合計）

**上司（役割切替で「上司」）**
- ダッシュボードで承認待ち件数（制度確認・受験申請・費用申請）と当月の取得件数を確認し、各承認画面へ移動
- 確認待ちの制度確認申請へ負担条件を設定して承認／却下（承認で資格マスタへ追加）
- 承認待ちの受験申請／費用申請を承認／却下（却下理由は必須。費用申請は承認時に回数上限を再確認）
- 全員の受験履歴・資格取得実績・費用申請履歴をタブで確認（検索・ステータス絞り込み）

## 費用申請の自動判定（結果報告時）

次の順序で判定し、すべて満たした場合だけ費用申請を自動生成する（画面表示とは分離した関数）。

```
1. 対象資格である（会社負担対象で、制度の条件を満たす）
   - 入社後一定期間内（例：日商簿記3級・ITパスポートは入社後3か月以内）
   - 合格時のみ対象（基本情報・応用情報）
   - 目標点数以上のみ対象（TOEICは会社指定の目標点数）
   - SAP資格は1年度にグループ全体で4回
2. 負担上限回数未満（承認済み費用申請の件数で数える）
3. 領収書が提出済み
```

対象外の場合は理由（例：「会社負担対象外の資格です」「合格条件を満たしていません」
「会社指定の目標点数に達していません」「負担回数の上限に達しています」「領収書が未提出です」）を表示する。

## 主な業務ルール（抜粋）

- 受験申請の**受験日は今日以降**であること（過去の日付は申請できない）
- 受験申請の重複は「同じ社員・同じ資格（qualificationId）・同じ受験日・却下されていない」場合だけ禁止。却下済みなら再申請できる
- 受験申請のステータス：承認待ち → 承認済み／却下 →（結果報告で）結果報告済み。処理済みの再承認・再却下・二重報告は不可
- 費用負担の判定には **実際の受験日** を使う（申請日・報告日は使わない）
- 回数は本人の「承認済み費用申請」の件数で数える。**自動生成時と上司の承認時の両方**で確認する
- 取得実績は「合格した場合」だけ登録。**報奨金は合格が条件で、領収書は条件にしない**（領収書は費用申請の条件）
- 制度確認申請は同じ資格名の「確認待ち」があれば重複として拒否。承認済み／却下済みの申請は再承認・再却下できない
- 基本情報技術者試験（Q004）と応用情報技術者試験（Q006）は別々に申請・承認・管理する
- 報奨金の判定と受験費用の判定は別々。領収書は受験費用の申請条件（報奨金の条件ではない）
